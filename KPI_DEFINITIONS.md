# Определения показателей

## Подтверждено в формулах Google Sheets

| KPI | Правило и уровень детализации |
|---|---|
| Звонки и обработка | Звонки = сумма D по дате и сотруднику КЦ. Обработка = сумма G. G = J + N + P + R + T, то есть действующая операционная метрика, а не число уникальных заявок. |
| План КЦ | В проверенной строке E = 37,5 × C, H = 3 × C, K = 1,25 × C; использовать вычисленные планы после проверки других строк. |
| Передачи | Операционная J считает строки передач по дате и сотруднику. Для уникального KPI считать разные CRM lead ID отдельно, с показателем покрытия идентификаторами. |
| Договоры | Действующий отчёт считает строки с датой договора. Уникальность договора и связь с лидом без идентификаторов не подтверждены. |
| Оплаты | Действующая метрика = строки договоров со статусом «Оплачено», сгруппированные по дате договора. Дату и сумму платежа этот показатель не представляет. |
| Брак и отказы | КЦ: первичные агрегаты D/E «Брак_и_отказ_КЦ». ОП: агрегаты F/G «Отказы_менеджеров». Статусы отдельных лидов — для проверки и детализации в пределах покрытия. |
| Часы и смены | В проверенной формуле Операционные_данные C часы вычисляются из статуса «РАБОТАЕТ» и длительности смены. Фактические часы не утверждены. Кадровый прогноз использует будущие смены графика. |
| Зарплата | K оклад пропорционален сменам по нормативам Q7/Q8, L = H × Q4, M = J × Q5, N = K+L+M, H = MAX(0;E−F−G). BI читает суммы K:N и не ведёт параллельное начисление. |

## Правила расчёта BI

- Отношения агрегируются как сумма числителя / сумма знаменателя. При нулевом или неизвестном знаменателе — «нет данных». Для конверсий между периодами показывать разницу в процентных пунктах. При сравнении неполных месяцев выравнивать длительность; при недоступности любой части выводить причину.
- Отдельно маркировать операционное отношение объёмов за период и конверсию когорты уникальных лидов. Когорта требует идентификаторов на всех этапах и согласованной даты включения. Объём обработок нельзя фильтровать по менеджеру или региону лида при отсутствии такого измерения.
- KPI обработки в час и передач в час делить на часы того же периода и сотрудника. Пока часы расчётные, так и подписывать. Считать численность и число человеко-смен разными KPI.
- Показывать ФОТ за месяц. Стоимость результата = сопоставимый ФОТ / результат. Не распределять месячные начисления по дням и направлениям без согласованного ключа.
- Консультации: числитель загрузки — назначенные доступные слоты, знаменатель — рабочие слоты после исключения выходных, блокировок и пустых смен. Ошибочные записи учитывать отдельно. Сигналы SLA опирать на M/N передач или на проверенные правила возраста и доступные даты. Возраст передачи и возраст текущего статуса не эквивалентны.
- Прогноз: факт с начала месяца + прогноз результата на оставшиеся подтверждённые плановые часы. Для базового сценария брать производительность на час, для консервативного снижать её на настраиваемый коэффициент, для оптимистичного менять конверсии в пределах 0–100%. Показывать долю заполненного расписания и используемые допущения. Цели 250 договоров и 125 оплат хранятся как редактируемые настройки. Дополнительные часы = max(0; требуемые часы − оставшиеся плановые часы). Дополнительные люди вычисляются при наличии нормативной смены и графика.
- Реальный ноль показывать только при подтверждённом покрытии. Для отсутствующего источника, неразрешённой размерности и неутверждённой формулы использовать пустое состояние с причиной.

## Что требуется подтвердить для приёмки

1. Где находится устойчивый ID лида на этапе первичной обработки, ID договора, связь договора с лидом и дата поступления платежа.
2. Где находится октябрьский первичный набор или равноценный подтверждённый октябрьский/ноябрьский срез на одинаковые даты.
3. Как отличить фактическую смену и фактические часы от запланированных, и где заданы лимиты направления по менеджерам.
4. Как трактовать повторные передачи, отменённые консультации, возврат из отказа и несколько платежей по одному договору.
