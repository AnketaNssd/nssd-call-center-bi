# Архитектура NSSD Call Center BI

React + TypeScript + Vite для интерфейса, ECharts для графиков, TanStack Query для запроса BI API. Node.js и PostgreSQL обслуживают данные. Рекомендуемый вариант размещения — один HTTPS origin для интерфейса и API, чтобы авторизация и политика cookies применялись к обеим частям. GitHub хранит публичный код и конфигурацию CI. GitHub Pages допустим только после подтверждения выбранной политики доступа; закрытая публикация Pages для организации требует GitHub Enterprise Cloud.

## Контур данных

1. Серверный процесс читает ограниченные диапазоны через Sheets values.batchGet со scope spreadsheets.readonly. Никаких write endpoints. На этапе настройки фиксирует sheet ID, заголовки и параметры периода для каждой книги.
2. Раз в пять минут запускается одна задача за пул источников. Автоматическое и ручное обновление используют один lock и одну политику задержек. Повторы 429/503 — экспоненциальная задержка с jitter. Проверенные диапазоны длинных вкладок разбиваются по размеру; исторические строки регулярно перепроверяются, так как Sheets не гарантирует append-only.
3. Результат проходит нормализацию во временных таблицах. При несовместимости схемы или конфликте ключей сохраняется обезличенная диагностика. Активные версии обновляются транзакционно; API возвращает состав версий, время последней успешной синхронизации и признак устаревания.
4. Таблицы Postgres: source_snapshot, sync_attempt, calendar_day, employee, employee_alias, region, operations_day, transfer, contract, payment, consultation_slot, call_center_shift, compensation_month и plan_target. Для статусов хранить наблюдение с observed_at отдельно от исходного event_at; не присваивать событию дату первого импорта.
5. Сервис аналитики агрегирует по типу факта и применяет только поддерживаемые измерения. Отдельные read models для потока событий, когорт, консультаций и ФОТ. Постраничная детализация с проверкой ролей. Для пользовательских ответов cache-control private, no-store.

## Защита и развёртывание

OIDC Google Workspace или корпоративный провайдер, явный список допущенных пользователей. Серверная сессия в Secure HttpOnly cookie. Роли viewer, finance и admin. Персональный ФОТ проверяется на сервере до SQL-запроса; права администратора нужны для изменения целей. Защищать и прямой URL API; CSRF для изменения целей и ручного обновления. Секреты и ключи использовать из защищённого хранилища окружения. При доступности workload identity предпочтительна аутентификация без JSON-ключа. В репозитории только код, шаблон конфигурации и схема.

GitHub Actions запускает проверки типов и тесты, собирает артефакт и развёртывает только из защищённой ветки в согласованное окружение. Пока владелец, доступ к записи и хостинг не подтверждены, публичная публикация данных не выполняется.

## Ворота приёмки

Сверка операционных показателей по дню и сотруднику; передач по CRM ID; договора и оплаты по существующей формуле и по фактической дате платежа при появлении источника. Контроль диапазона октября, рабочего времени девяти регионов, зарплатного месяца и HTTP 401/403 на прямом доступе к API. Проверка недоступного источника, повторной синхронизации и пропусков данных. Проверка фильтров и детализаций на мобильном и настольном интерфейсе.
