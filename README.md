# NSSD Call Center BI

Текущая сборка охватывает ноябрь 2026. Интерфейс использует только данные из источников. При отсутствии данных показывает причину.

## Запуск

1. Установите Node.js 22. Выполните npm ci, npm test и npm run build.
2. Скопируйте .env.example в .env. Укажите четыре ID книг из ТЗ.
3. Включите Google Sheets API. Предоставьте сервисной учётной записи доступ «Читатель» ко всем четырём книгам и настройте Application Default Credentials. При использовании JSON-ключа храните его вне checkout и укажите путь через GOOGLE_APPLICATION_CREDENTIALS.
4. Создайте Google OAuth client типа Web application с URL обратного вызова APP_ORIGIN/auth/callback. Добавьте секрет в окружение. Задайте NSSD_ACCOUNTS как JSON-словарь адресов и ролей viewer, finance или admin.
5. Выполните node --env-file=.env server/index.mjs. Откройте http://localhost:8080.

Синхронизация выполняется при старте, раз в пять минут и по кнопке. При сбое приложение помечает последнюю копию как устаревшую. Снимок и сессии хранятся в памяти. Цели сохраняются в NSSD_STATE_DIR. Текущий runtime рассчитан на один экземпляр.

Дополнительные соответствия имён можно задать через NSSD_AGENT_ALIASES в виде JSON-словаря. Храните этот словарь только в окружении сервера.

## Публикация

GitHub Actions тестирует код и собирает приложение. Для постоянного URL нужен Node.js-хостинг с HTTPS и защищённым хранилищем секретов. Укажите NODE_ENV=production и APP_ORIGIN с адресом HTTPS. Проверьте ответ 401 без входа и 403 для роли viewer на персональной зарплате.

## Границы текущей сборки

Предусмотрены адаптивный интерфейс, две темы, операционные KPI, динамика, фильтры, ранжированные таблицы, смены менеджеров, контроль покрытия CRM ID, зарплатный раздел с ролью и ноябрьский прогноз по часам. Оплаты отражают статус договора на дату договора. В работе остаются когортная связка, интерактивная карта, полноценная матрица консультаций, персональные карточки, расширенный SLA, прогноз численности и сравнение двух произвольных периодов.

## Личный дашборд без отдельного входа — Google Apps Script

Эта сборка использует аккаунт владельца и те же формулы обработки. Доступ в манифесте задан как «Только я». Скрипт читает таблицы через Google Sheets API со scope spreadsheets.readonly. Снимок обновляется при открытии, затем проверяется раз в минуту, а повторное чтение таблиц выполняется не чаще одного раза за пять минут при открытом дашборде. Кнопка ручного обновления выдерживает минимальную паузу 30 секунд.

1. Выполните npm ci и npm run build:apps-script.
2. Создайте проект в Google Apps Script под аккаунтом, который видит четыре книги. Добавьте файлы Code.gs, Core.gs и Index.html из apps-script/dist. Включите отображение манифеста в настройках проекта и скопируйте appsscript.json. При использовании отдельного проекта Google Cloud включите в нём Google Sheets API.
3. В настройках проекта добавьте четыре свойства NSSD_SHEET_MAIN, NSSD_SHEET_CALENDAR, NSSD_SHEET_PAYROLL и NSSD_SHEET_ROSTER. Значения — ID книг из ТЗ. Свойства хранятся только в Apps Script.
4. Выберите «Развернуть» → «Новое развёртывание» → «Веб-приложение». Выполнять от имени владельца, доступ «Только я». Подтвердите чтение таблиц в Google и сохраните ссылку, оканчивающуюся на /exec.
5. Откройте /exec на рабочем компьютере под тем же аккаунтом. Проверьте дату обновления, сравните контрольный день с таблицами и откройте ссылку в другом профиле, чтобы проверить отказ в доступе.

Клиентские ресурсы уже включены в Index.html. Домена, сервисного аккаунта и Node.js-хостинга для этой версии не требуется.
